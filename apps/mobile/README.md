# apps/mobile

The AMPM client and team apps: Expo SDK 58 with Expo Router, NativeWind on the tokens preset, phones and tablets, and the web export that is the browser version of the client portals. Setup and the common scripts are in the root [README](../../README.md); the rules are `.claude/rules/ui.md`, `styling.md` and `offline.md`.

- `src/app/` the routes (Expo Router). `index` sends a signed-in person to their place (staff to the first workspace area their roles grant, clients to `/portal`), `sign-in` is the development sign-in and `gallery` the component gallery. A top-level route hands its screen the phone tab bar (`<LeadsListScreen tabBar={<AppTabBar />} />`); detail and form routes take none.
- `src/features/<feature>/` screens, components and hooks by feature, built from the Peacock Night kit (`docs/design/peacock-night.md`) on `Screen` and `ScreenHeader`, never a hand-rolled scroll view with insets
- `src/navigation/` the stack and the navigation around it: the phone tab bar (`AppTabBar`), the staff rail and the client top navigation that the layout draws from 768 (`AppChrome`), the areas each audience sees, and the one sign-out (`useSignOut`, drawn by `SignOutButton` on the account screen and under the account and portal error states, so it stays in reach when `/me` fails and the tab bar keeps only More, and run by `useGoToSignIn` when a 401 sends a screen back to sign-in); the stack has a web variant that leaves colours to CSS
- `src/lib/` the public environment (`EXPO_PUBLIC_*`) and the session (`useIsSignedIn` for a component that renders from it)
- `src/test/` the test render under the app's providers and the API helpers (`renderWithApi`, the envelopes). Jest runs the app's code through the React Compiler, as Metro does (`jest.config.mjs`), so the tests check the code that ships

```bash
pnpm --filter mobile dev       # Metro on 8082; press i for the installed development build (s switches to Expo Go); http://localhost:8082 for the web build
pnpm --filter mobile typecheck
```

Native dependencies are added with `pnpm --filter mobile exec expo install <package>`, never with a plain `pnpm add`.

## Native builds (D-152)

One store app for staff and clients: `com.ampmverse.app` on iOS and Android, phones and tablets. `app.json` describes the store app, and `app.config.ts` derives two variants from `APP_VARIANT`, each installing beside the store app: development (`com.ampmverse.app.dev`, "AMPM Dev") and preview (`com.ampmverse.app.preview`, "AMPM Preview"). `ios/` and `android/` are generated by `expo prebuild` and never committed; change `app.json`, `app.config.ts` or a config plugin instead, then regenerate.

Development builds on this machine need Xcode, the Android SDK and Java 17, but no account. Each one builds AMPM Dev, installs it and starts Metro on 8082:

```bash
pnpm --filter mobile ios
```

```bash
pnpm --filter mobile android
```

On the Android emulator `localhost` is the emulator itself, so forward the local API port first: `adb reverse tcp:3900 tcp:3900`.

Native builds link Expo's precompiled modules, which must match one another, so keep every Expo package at the version the SDK expects. A drifted patch builds cleanly and then crashes at launch on a missing symbol, which Expo Go and the web export never show. `expo install --check` lists the drift; only the Jest 29 to 30 major is expected there for now. `expo install` cannot write a package's config plugin into `app.config.ts`, so add it to `plugins` in `app.json` by hand. After a change to the native configuration, regenerate the projects:

```bash
pnpm --filter mobile native:prebuild
```

EAS builds (`eas.json`) need an Expo account for AMPM and one `npx eas-cli@latest init` in this folder, which writes the project id into the app config; store builds also need AMPM's Apple Developer and Google Play accounts. Every profile builds on Node 24 with corepack's pnpm.

| Profile              | Builds                                                                   |
| -------------------- | ------------------------------------------------------------------------ |
| `development`        | the development client: an iOS simulator build and an Android APK        |
| `development-device` | the development client for a registered iPhone                           |
| `preview`            | an internal test build against the production API with AMPM's sign-in    |
| `production`         | the store build; EAS keeps the build number and raises it on every build |

```bash
npx eas-cli@latest build --profile preview --platform all
```
